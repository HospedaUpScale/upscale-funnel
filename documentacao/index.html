1 Arquitetura da VPS

O projeto já contém a imagem de produção. O container serve a aplicação na porta 80, executa as migrações no primeiro início e mantém Nginx e PHP-FPM no mesmo serviço.

DockerfileImagem PHP 8.3, extensões e arquivos da aplicação.
deploy/nginx.confRotas do painel, APIs, arquivos estáticos e PHP.
deploy/start.shPermissões, migrações e inicialização dos processos.
A publicação acontece pela imagem Docker; não é necessário criar pastas públicas manualmente nem usar .htaccess.

2 Variáveis de ambiente

Crie o arquivo .env na VPS a partir de .env.example. Não envie esse arquivo ao repositório.

.env — produção
APP_ENV=production
BASE_DOMAIN=oferta.seudominio.com.br
CARD_BASE_URL=https://oferta.seudominio.com.br
DEFAULT_WORKSPACE_SLUG=sincero

ADMIN_USER=admin
ADMIN_EMAIL=admin@seudominio.com.br
ADMIN_PASSWORD=troque-por-uma-senha-forte
SUPER_ADMIN_TOKEN=gere-um-token-longo-e-aleatorio
ENFORCE_API_TOKEN=true

DB_DRIVER=mysql
DB_HOST=host-do-banco
DB_PORT=3306
DB_DATABASE=upscale
DB_USERNAME=upscale
DB_PASSWORD=senha-do-banco
Troque obrigatoriamente ADMIN_PASSWORD, SUPER_ADMIN_TOKEN e a senha do banco antes de publicar.

3 Publicação e atualização

Exemplo para uma VPS onde o proxy público encaminha para a porta local 8080. O volume preserva SQLite, sessões e estado de migração entre recriações.

Shell Linux na VPS
git pull
docker build -t booster-110x .
docker stop booster-110x 2>/dev/null || true
docker rm booster-110x 2>/dev/null || true
docker run -d \
  --name booster-110x \
  --restart unless-stopped \
  --env-file .env \
  -p 127.0.0.1:8080:80 \
  -v "$(pwd)/storage:/var/www/html/storage" \
  booster-110x

Se o MySQL estiver em outro container, conecte ambos à mesma rede Docker e use o nome do serviço em DB_HOST.

4 Domínio, proxy e HTTPS

Aponte o DNS do subdomínio para a VPS. No Nginx do host, encaminhe HTTPS para o container e mantenha os cabeçalhos de proxy.

/etc/nginx/sites-available/booster-110x
server {
  listen 80;
  server_name oferta.seudominio.com.br;

  location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }
}
Depois de validar o DNS, emita o certificado TLS com a ferramenta adotada na VPS, como Certbot ou Caddy. O endereço final do card deve responder somente por HTTPS.

5 Integração por iframe

Use a raiz da aplicação e informe o workspace. O listener ajusta a altura automaticamente e elimina a rolagem interna do iframe.

Bloco para a página de obrigado
<div style="width:100%;max-width:680px;margin:0 auto">
  <iframe
    id="booster-110x"
    src="https://oferta.seudominio.com.br/?workspace_id=2&nome={{nome}}"
    title="Oferta Booster 110X"
    style="width:100%;height:460px;border:0;display:block"
    scrolling="no"
    loading="eager"></iframe>
</div>

<script>
window.addEventListener('message', function (event) {
  if (event.origin !== 'https://oferta.seudominio.com.br') return;
  if (event.data && event.data.tipo === 'dx:altura') {
    document.getElementById('booster-110x').style.height = event.data.altura + 'px';
  }
});
</script>
O Nginx interno ainda usa frame-ancestors *. Em produção, substitua o curinga pelos domínios exatos das plataformas que podem incorporar o card.
